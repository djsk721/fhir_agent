# MIMIC과 Synthea 고정 환자 검증 보고서

## 검증 목적

동일 환자·원천 행·참조 자료에서 새 변환 로직의 회귀 여부를 확인한다. 이미 관찰한 환자를 다시 사용한 **개발 파일럿**이다. 표본 확대, 성능 우위 검정, 새 환자에서의 본평가와는 구분한다.

| 자료 | 준비 환자 | 평가 환자 | 준비 원천 행 | 평가 원천 행 | 독립 FHIR 참조 |
| --- | ---: | ---: | ---: | ---: | --- |
| MIMIC-IV Demo v2.2 | 1 | 1 | 95 | 83 | PhysioNet 공개 MIMIC-IV on FHIR Demo v2.1.0 |
| Synthea | 1 | 2 | 119 | 322 | 원천 CSV와 같은 생성 실행의 FHIR R4 |

MIMIC은 기존 Demo 코호트와 동일한 환자만 DB에서 읽기 전용으로 추출했다. MIMIC Observation은 현재 추출 명세의 `labevents` 범위다. Synthea는 동일한 생성 실행을 확인하기 위해 원천 CSV 네 개와 참조 FHIR 세 개의 SHA-256을 대조한 뒤 기존 환자를 다시 추출했다. 평가 행 수는 MIMIC에서 Patient 1, Encounter 1, Condition 15, Observation 66건, Synthea에서 각각 2, 21, 16, 283건이다. 두 자료 모두 이 추출 범위 안에서 원천 행에 LIMIT를 적용하지 않았다. 상세 출처와 파일 해시는 `artifacts/fixed-pilot-20261121/{mimic,synthea}/provenance.json`에 있다.

Synthea 원본 생성기 버전 표기는 `master-branch-latest`다. 이번 재실행은 해시가 일치하는 실제 입력 파일과 저장된 스냅샷을 기준으로 재현한다. 생성기를 처음부터 다시 실행해야 하는 본실험에서는 릴리스나 commit과 생성 옵션을 별도로 고정한다.

## 고정과 평가 범위

환자 역할은 `split --fixed-roles`로 고정하며, 실제 추출이 끝나면 `cohort-lock`으로 준비·평가 스냅샷, 독립 FHIR, 매핑 참조의 변경을 감지한다. 모델 요청에는 평가용 정답을 포함하지 않는다. 자물쇠 역할을 하는 설정 파일이나 환자 식별자는 소스 코드에 넣지 않는다. 두 코호트에서 `cohort-verify`를 통과한 뒤 잠금 파일을 모델 실행에 사용한다.

RQ1의 비교용 참조는 출력을 보고 작성한 규칙과 분리했다. MIMIC 15개, Synthea 18개 규칙을 대상으로 하는 **부분 참조**다. 연산 설정의 완전 일치에는 표현의 차이도 반영되므로, 이번 점수는 본실험의 전문가 합의 정답이나 전체 변환 품질 점수로 해석하지 않는다. [평가용 매핑 범위](../experiments/references/README.md)

## 변경 내용과 분모

- 업무키를 선언한 Patient·Encounter는 해당 키를 ID로 사용한다. 연관 데이터의 FK는 동일한 ID 표현을 사용해야 한다. 행 단위 생성 실패에는 실패 매핑 경로를 기록한다.
- Synthea 준비 예시에 숫자형과 문자형 Observation을 모두 포함한다. 각각의 자료형은 FHIR `value[x]` 분기와 원천 보존 검사로 확인한다.
- 출력을 바꾸지 않고 비교 사본에만 Synthea 패널 구성요소 전개와 코드화 검사값의 텍스트 투영을 적용한다. 원천 행/생성 리소스 수, 독립 FHIR의 비교 이벤트 수, HL7 Bundle 통과는 각각 다른 분모를 사용한다.
- 참조 FHIR의 전체 평가 이벤트 기준 필드 정확도, 이벤트 매칭률, 매칭된 이벤트만의 필드 정확도를 나누어 보고한다. 기대 Reference 커버리지는 독립 참조의 기대 링크를 분모로 삼으므로, 생성된 링크만 대상으로 한 해소율과 구분한다.
- Synthea Observation의 코드 비교에는 CSV에서 직접 확인할 수 있는 코드 값만 포함한다. 참조 FHIR의 코드 체계·표시문, 활력징후 프로파일 요건 전체를 맞췄다는 의미는 아니다. 코딩 적합성 오류는 HL7 결과에서 별도로 확인한다.
- MIMIC의 시간대 없는 원천 시각은 이전 파일럿 설정(`Z`)을 유지했다. 검사 이벤트 66건을 원천 업무키로 따로 대조한 결과 현지 시각 숫자는 66건 모두 같았다. UTC로 해석하면 참조와 같은 순간이 0건, `America/New_York`로 해석하면 66건이었다. 단일 환자·단일 오프셋의 진단이며 이번 평가 점수에는 적용하지 않았다. 본실험 전 다른 시기의 자료와 시간대 근거를 확인하고 DST 중복·누락 시각 정책을 고정해야 한다. [참조 FHIR 변환 SQL](https://github.com/kind-lab/mimic-fhir/blob/v2.1.0/sql/fhir_observation_labevents.sql)

## 재현과 검증 환경

`gpt-oss:20b`와 FHIR 스키마 임베딩 모델을 로컬 Ollama로 실행했다. 실행 중 두 모델의 메모리가 모두 GPU에 배치됐음을 확인했다. MIMIC RAG와 Synthea는 동일한 정책 파일을 사용한다. 두 평가가 일부 시간대에 같은 Ollama를 사용했으므로 파일럿의 경과 시간으로 방식 간 처리 속도 우위를 판단하지 않는다. HL7 Java Validator는 FHIR R4 4.0.1, 원격 용어 서버 비활성화(`-tx n/a`)로 실행했다. 원격 용어 서버를 끈 상태에서도 로컬 패키지에 근거한 용어·프로파일 검사는 수행된다.

고정 환자 집합, 코호트·정책 잠금, 생성·보정 checkpoints와 산출물은 `artifacts/fixed-pilot-20261121/`에 저장했다. 트래킹하지 않는 로컬 폴더이므로 학술 제출용 문서에는 환자 식별자와 원천 레코드를 넣지 않았다. 기존 잠금으로 평가를 반복하려면 동일 코드와 입력을 사용하고 결과 디렉터리만 새로 지정한다. 코드, 설정 또는 정답이 바뀌면 해당 잠금을 새로 생성한다.

소프트웨어 전체 테스트는 **148건 통과**했다. 고정 환자 역할의 재현성, 재해시한 원천 자료라도 저장된 잠금과 다르면 거부하는 동작, 독립 참조 변경 차단, 준비 Profile의 출처, 두 데이터셋의 타입 및 참조와 새 평가 지표를 확인했다.

## Hybrid 회귀 검증

MIMIC RAG와 Synthea 모두 초기 Encounter Profile을 첫 시도에 만들었다. MIMIC RAG에서는 Patient가 `deceasedBoolean`과 `deceasedDateTime`을 한 입력에 동시에 쓰는 규칙을 제안해 Profile 생성 단계에서 거부됐고, 초기·보정 Hybrid 모두 83행 중 82행만 변환됐다. 보정 후 HL7은 한 차례 패키지 초기화 오류로 종료됐다. 산출물을 그대로 다시 검사하니 HL7 error/fatal은 0이었으나, 누락된 Patient에 대한 미해결 참조 때문에 **종합 검증은 불합격**이었다. 초기 실행 결과는 그대로 두고 재검사 결과를 별도 파일로 보존했다.

Synthea는 초기·보정 Hybrid 모두 322행을 변환했다. 숫자형 Observation 210건은 `valueQuantity`, 문자형 73건은 `valueString`으로 변환됐다. 비교용으로 패널 부모 16건을 구성요소 89건으로 대체하면서 독립 참조의 Observation 168건이 241개 비교 이벤트가 됐다. 초기·보정 Hybrid 모두 전체 비교 이벤트 **280/280**을 매칭했고 기대 참조 커버리지는 **100%**였다. 원천 Observation 42건에는 동일 키의 FHIR 비교 이벤트가 없어 매칭률 100%가 출력 집합의 완전 일치를 뜻하지는 않는다. 보정은 Encounter 상태 누락을 줄였지만 Observation의 활력징후 패널 구조와 로컬 용어 검사 오류가 남았다.

MIMIC RAG 보정은 준비 자료의 차단 오류 6건을 해결했고 새 차단 오류는 없었으나, 준비 검사를 전부 통과한 Profile은 0종이었다. 이 파일럿에서는 보정 전후의 참조 정확도와 이벤트 매칭률이 같았다. 매칭된 이벤트만의 점수가 높더라도 검사 이벤트 매칭률이 떨어지면 전체 원천 충실도는 낮다.

## 본평가 전 확인할 항목

1. MIMIC Patient의 `deceased[x]`가 한 행에서 하나의 타입만 선택하도록 생성 실패를 점검한다. 조건 리소스 생성과 환자·입원 참조 연결을 함께 확인하고, 시각 해석과 DST 정책을 먼저 고정한다.
2. Synthea의 비교용 전개와 실제 출력의 FHIR 적합성을 구분한다. 실제 출력에서는 혈압 등 활력징후 패널 구조와 코드·단위·용어 바인딩을 확인한다.
3. 부분 매핑 참조를 전문가 검토 범위로 확장하고, 합의한 기준과 설정을 잠근 뒤 새 평가 환자를 고른다. 평가 환자가 1명인 MIMIC과 2명인 Synthea의 이 결과는 회귀 진단용이다. 성능 크기, 처리 시간 우위, 실제 기관 일반화의 결론을 내리지 않는다.

실행 절차는 [연구 프로토콜](./research_protocol.md), 본평가 설계는 [연구계획서](./research_plan.md)를 따른다.
